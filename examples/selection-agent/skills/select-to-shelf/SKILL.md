# 选品到上架

用户已经给出商品。按顺序调用，上一步的返回原样交给下一步。任一步失败就停，说明原因，不要写成已上架。

**开场先弹站点，再搜。** 没有 `set_marketplace` 成功之前，不要调用 `search_products` / `research_candidates` / `score_and_save`。检索还没打完分之前不要回复用户。打完分后先只弹上架相关的 `ask_user`。那一轮不要写结论，也不要调用 `select_listing` 或 `browser_open`。没点提交之前不要打开浏览器。用户点了上架提交之后的下一轮，再写出四块，并同时打开模拟后台。

0. **每次新开选品（用户给出商品词）的第一步必须先弹站点。** 先只调用一次 `ask_user`：「选哪个站点？」选项「德国站」「美国站」，然后停，不要搜、不要打分。用户点了提交之后立刻 `set_marketplace`，把选项原样传入，再进入第 1 步。德语/英语商品词、类目名都不算已选站。只有用户原话里明确写了「德国站」或「美国站」时，可以跳过弹窗，但仍必须先 `set_marketplace` 再搜。整轮（选站到写完结论）绑这个站，不要中途换站。磁盘里以前的站点不算数。
1. `search_products`。必须已经 `set_marketplace`。`query` 用用户原话里的商品词。用户没给价格带就不要传 `minPriceUsd` 和 `maxPriceUsd`。货架价货币看返回的 `currency`；`priceUsd` 只是字段名。德国站是欧元，美国站是美元。搜到 0 条就停，不要换词重试，也不要打开后台。
2. `research_candidates`。候选池原样传入。不要自己补搜索量、成本或评论数。
3. `score_and_save`。`candidates` 原样传入，失败清单放 `knownFailures`。这一步先不要回复。
4. `prepare_case`。没记下的采购价、模费、起订量和试样结果保持空，不要补。
5. 这一轮只调用一次 `ask_user`，然后停。不要写结论、排行榜、说明、缺口，不要调用 `select_listing`，不要调用 `browser_open`。报价和试样已经记下时，这一题就够：
   - 「上架哪一条到模拟店？」选项是排行榜前 4 名的商品标题，再加「先不上架」。
   还没记下时，按这个顺序问五题：
   - 「工厂报价怎么处理？」选项「先不记」「我下一条消息补采购价、模费和起订量」
   - 「试样结果怎么处理？」选项「还没试样」「我下一条消息按编号补结果」
   - 「链接草稿要确认吗？」选项「先不确认」「确认现有草稿」
   - 「上架哪一条到模拟店？」选项是排行榜前 4 名的商品标题，再加「先不上架」。建议动作是放弃也要放进选项。结论里照实写放弃，不要改成观察或上架。
   - 「要不要发起询盘？」选项「先不询盘」「按准备清单发起询盘」
6. 等用户点了提交、`ask_user` 返回之后，再按 `AGENTS.md` 的回复格式写出四块：结论、排行榜、说明、缺口。贴排行榜前先调用技能 `ranking-images`。回复第一行必须原样复制 `score_and_save`、`save_report` 或 `prepare_case` 返回的 `imageMarkdown`。没有这个字段就调用 `render_board`，再用返回的 `image` 写成 `![选品结果](路径)`。路径不要改，不要换成网址，不要只出文字表。排行榜仍用 `score_and_save` 的 `markdown`，图片列和方块条原样保留。结论那一句放进引用块。说明用表，三列是商品、为什么、要验，每格一句。这一次不要写发布结果。报价已经是「已报价」、试样已经是「已记录」时，不要在结论里写「不是真实报价」或「还没试样」。名字用 `prepare_case` 的返回。选了「确认现有草稿」就调用 `confirm_listing`。选了「按准备清单发起询盘」就调用 `save_inquiry`：asin 和 title 优先用用户点中的上架那一条；没点上架就用排行榜第 1 名；items 不传。选了两个「我下一条消息…」里的任一个，就不要打开浏览器，请用户把数字或试样结果发来。用户点了一个商品标题，并且没有选「我下一条消息…」，这一轮写出四块，并同时做第 8 步。点了「先不上架」或跳过，写出四块，补一句「未上架」，不要打开浏览器。不要用散文再问一遍询盘。
7. 用户已经给出采购价、模费、起订量、汇率、头程、尾程或佣金时调用 `save_quote`，只传用户给出的数字。汇率是 1 欧元兑多少人民币（美国站演示也先按这个字段记），头程和尾程是货架货币每件，佣金是 0 到 1 的小数。用户按编号给出试样结果时调用 `save_sample`，结果照抄原文。缺任何一项都不要补默认值，也不要算月销量。
8. 先 `select_listing`。sku、title、priceEur、category 只用 `search_products` 里和用户点中的标题对应的那一条，priceEur 就是那里的 priceUsd（当前站货币）。对不上就停，不要编价格，也不要改成档案提案。然后立刻 `browser_open`，**url 必须是 `http://127.0.0.1:7455/`**，不要空参数，也不要先 snapshot。若页面仍是 `about:blank`，再 `browser_navigate` 到同一地址。账号 `seller`，密码 `demo`。登录后依次点开这些页，只核对，不要改标题、价格、税号、编码、件数或预算：
   - 「准备」
   - 「编辑链接」。标题和售价必须是点中的那条。演示图、搜索页原文、演示编码、税费说明已经在页面上。卖点留空。
   - 「入库」。件数是空的。
   - 「广告」。状态是未投放。
   然后点 `set_marketplace` / `prepare_case` / `select_listing` 返回的 `publishLabel`（德国站是「发布到德国站」，美国站是「发布到美国站」）。没有变成已上架就停，不要说已上架。
   最后点「买家页面」，或打开 `http://127.0.0.1:7455/#shop`。买家看到的标题和售价必须是点中的那条。购物车点了也不能下单。
   不要打开真实亚马逊卖家后台。做完用两句说明：发布结果，以及买家页面是否看得到。不要再问询盘。

数字只来自工具。打分不心算。建议动作只有上架、观察、放弃。总分达到 0.65 且没有封顶风险时，建议动作写上架。
