# 选品到上架

用户已经给出商品。不要再问站点或价格带。按顺序调用，上一步的返回原样交给下一步。任一步失败就停，说明原因，不要写成已上架。

检索还没打完分之前不要回复用户。结论必须先写出来，然后才弹出是否上架。

1. `search_products`。`query` 用用户原话里的商品词。用户没给价格带就不要传 `minPriceUsd` 和 `maxPriceUsd`。当前档案是德国站，售价是欧元；`priceUsd` 只是字段名。搜到 0 条就停，不要换词重试，也不要打开后台。
2. `research_candidates`。候选池原样传入。不要自己补搜索量、成本或评论数。
3. `score_and_save`。`candidates` 原样传入，失败清单放 `knownFailures`。这一步先不要回复。
4. `prepare_case`。没记下的采购价、模费、起订量和试样结果保持空，不要补。
5. 先按 `AGENTS.md` 的回复格式写出四块：结论、排行榜、说明、缺口。排行榜用 `score_and_save` 的 `markdown`。准备三段放在表后面，各用一个短列表。这一次不要写发布结果。
6. 四块写完后调用一次 `ask_user`，按这个顺序问四题：
   - 「工厂报价怎么处理？」选项「先不记」「我下一条消息补采购价、模费和起订量」
   - 「试样结果怎么处理？」选项「还没试样」「我下一条消息按编号补结果」
   - 「链接草稿要确认吗？」选项「先不确认」「确认现有草稿」
   - 「上架哪一条到模拟店？」选项是排行榜前 4 名的商品标题，再加「先不上架」。建议动作是放弃也要放进选项。结论里照实写放弃，不要改成观察或打样。
   名字用 `prepare_case` 的返回。选了「确认现有草稿」就调用 `confirm_listing`。选了两个「我下一条消息…」里的任一个，就不要打开浏览器，请用户把数字或试样结果发来。用户点了一个商品标题，并且没有选「我下一条消息…」，才做第 8 步。点了「先不上架」或跳过，不要打开浏览器，补一句「未上架」。
7. 用户已经给出采购价、模费、起订量、汇率、头程、尾程或佣金时调用 `save_quote`，只传用户给出的数字。汇率是 1 欧元兑多少人民币，头程和尾程是欧元每件，佣金是 0 到 1 的小数。用户按编号给出试样结果时调用 `save_sample`，结果照抄原文。缺任何一项都不要补默认值，也不要算月销量。
8. 先 `select_listing`。sku、title、priceEur、category 只用 `search_products` 里和用户点中的标题对应的那一条，priceEur 就是那里的 priceUsd。对不上就停，不要编价格，也不要改成档案提案。然后再打开 `http://127.0.0.1:7455/`，先 `browser_open`。账号 `seller`，密码 `demo`。登录后依次点开这些页，只核对，不要改标题、价格、税号、编码、件数或预算：
   - 「准备」
   - 「编辑链接」。标题和欧元价必须是点中的那条。演示图、搜索页原文、演示编码、VAT 说明已经在页面上。卖点留空。
   - 「入库」。件数是空的。
   - 「广告」。状态是未投放。
   然后点「发布到德国站」。没有变成已上架就停，不要说已上架。
   最后点「买家页面」，或打开 `http://127.0.0.1:7455/#shop`。买家看到的标题和欧元价必须是点中的那条。购物车点了也不能下单。
   不要打开真实亚马逊卖家后台。做完用两句说明：发布结果，以及买家页面是否看得到。不要再问询盘。

数字只来自工具。打分不心算。建议动作只有打样、观察、放弃。
