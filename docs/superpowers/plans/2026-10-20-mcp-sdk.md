# 官方 MCP SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace tah's hand-rolled MCP client with `@modelcontextprotocol/client`, and expose resources, prompts, and remote HTTP through the existing tool loop plus `/name` on ChatHost.

**Architecture:** `McpBackend` stays the seam. stdio and HTTP backends wrap an official `Client`. `mcpPlugin` still registers only the remote server's tools. `contextToolsFromMcp` adds up to three fixed tools after every server has connected. Slash expansion is a pure function called from `ChatHost` and line-mode `tah chat`.

**Tech Stack:** TypeScript, Node 22, `@modelcontextprotocol/client` v2 (protocol 2026-07-28). Tests use `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-20-mcp-sdk-design.md`

## Global Constraints

- Official package is `@modelcontextprotocol/client`. stdio transport import is `@modelcontextprotocol/client/stdio`. Do not add `@modelcontextprotocol/sdk` (v1).
- No OAuth, no elicitation UI, no sampling, no resource sidebar, no control-plane page changes, no reconnect, no `listChanged` reload, no `tah.config.json` watch.
- `command` and `url` are mutually exclusive. `--mcp` / `--mcp-arg` still replace the whole list with one stdio server.
- Service label: stdio is `command` and `args` joined by a single space; HTTP is the `url` string. Duplicate labels fail startup with `duplicate MCP server label: <label>`.
- Fixed tool names are exactly `list_resources`, `read_resource`, `get_prompt`. A clash with a remote tool fails with `Duplicate tool name: <name>`.
- Binary resource text is `已省略（<mime>）`. Missing mime uses `application/octet-stream`.
- Prompt slash body is wrapped in `<mcp_prompt name="...">`, message texts joined by a blank line.
- Headers never appear in error text.
- HTTP failure text is `MCP server failed (<url>): Streamable HTTP: <reason>; SSE: <reason>`.
- Commits follow `~/.cursor/skills/code-commit/SKILL.md`. Never push. Never commit `.superpowers/`.
