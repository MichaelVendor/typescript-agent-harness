# TUI 图片设计

状态：✅ 已实现（v1.5）

## 背景

`tah chat` 的 TUI 把模型回复渲染成终端文本。完整的 Markdown 块用 `marked-terminal` 画成粗体、列表、表格和代码块。用户消息、工具行、待办、审批卡片和提问卡片都是字符界面。

图片附件存在 `<cwd>/.tah/attachments/`，网页工作台可以粘贴、拖入并显示。TUI 目前丢掉附件元数据，回复和工具结果里的图片路径也只是文字。

## 目标

- `tah chat` 的 TUI 在滚动区里画出图片。
- macOS、Linux、Windows 都能从系统剪贴板读入图片。拖入或粘贴的本地图片路径也收成附件。
- 画出三类图：这条用户消息的图片附件；回复里的 Markdown 图片和裸图片路径；工具结果里的图片路径。
- 收进来的图走现有附件库。发给模型的路径说明和看图行为不变。
- 按终端认识的协议发控制序列：Kitty 占位字符、iTerm 内联图、Sixel。认不出协议时不发序列。

## 非目标

- 不在 `tah run` 里收图或画图。
- `--plain` 和非终端输出不发图片控制序列。
- 这一轮不在 TUI 里收文本文件等非图片附件。
- 不下载网页地址，不渲染 `data:`。
- 不用字符拼图，不引入图片解码库。

## 画面里出现什么

文字保留。图加在提到它的那一块下面。同一块里同一条路径只画一次。一条回复或一次工具结果最多画 20 张，多出来的只留路径。

| 位置 | 画什么 |
| --- | --- |
| 用户消息 | 该消息附件里的 png、jpeg、webp、gif，画在文字下面。重新打开会话时一样，历史仍只带最近 3 轮 |
| 回复 | 一块 Markdown 写完后，从中找出 `![说明](路径)`，以及单独一个词、解析后是工作区里的图片文件 |
| 工具行 | 工具结果文本里的这类路径，画在该行下面。`saved .tah/browser/page.png` 落在这里 |

路径先做成绝对路径，再取真实路径。真实路径必须落在当前工作区里面。网页地址、`data:`、工作区外面的路径保持文字。

裸路径按空白切开。路径里夹有空格时不当作裸路径。相对路径相对工作区解析。扩展名是 `png`、`jpg`、`jpeg`、`webp`、`gif` 之一，且文件头是这四种图片，才画。

## 图片怎么进入输入框

存储用现有的 `createAttachmentStore(cwd)`，根目录 `<cwd>/.tah/attachments/`。发送仍是 `send(文字, 附件 id)`。只有图片、没有文字，也可以发送。

**剪贴板。** 输入框空闲或正在排队下一条时，按 Alt+V：

| 系统 | 读取方式 |
| --- | --- |
| macOS | 系统粘贴板，取出 PNG 字节 |
| Linux | 先 `wl-paste --type image/png`；命令不存在时再 `xclip -selection clipboard -t image/png -o` |
| Windows | PowerShell 读剪贴板图片并写出 PNG |

字节必须能认出是 png、jpeg、webp 或 gif，然后写入附件库。命令本身找不到，才是 `image clipboard unavailable`；命令跑完但没有图片字节，是 `clipboard has no image`。

输入框没在接收文字时不读剪贴板，也不改待发送列表。这包括审批卡片、提问卡片和会话选择。待发送列表的 Backspace 只在输入框正在接收文字、且框内为空时去掉最后一张。

**拖入或粘贴的路径。** 一次粘贴整段都是路径（一行一个，或用空白隔开），且每一条都是已存在、可读的图片文件时：把文件拷进附件库，这段文字不留在输入框里。这些源文件可以在工作区外面。其中任何一条不是这样的文件时，整段仍插入输入框，不收成附件。

**待发送。** 输入框上方一行显示这些图片的文件名。输入框为空时，Backspace 去掉最后一张。一条消息最多 20 张图片，单张最大 20 MiB；超出时用附件库现有的 `AttachmentError` 文案，这张不收。排队的消息带着这些附件，队列行里显示文件名。

## 终端里怎么画

启动时读一次环境变量，选定一种协议：

| 条件（按此顺序） | 协议 |
| --- | --- |
| `KITTY_WINDOW_ID` 有值，或 `TERM_PROGRAM` 为 `ghostty`，或 `TERM` 为 `xterm-kitty`，或存在 `WEZTERM_EXECUTABLE` / `TERM_PROGRAM=WezTerm` | Kitty 占位字符 |
| `TERM_PROGRAM` 为 `vscode` 或 `iTerm.app` | iTerm 内联图，高度按格子写死 |
| `WT_SESSION` 有值，或 `TERM` 为 `foot` | Sixel |
| 其余 | 不发控制序列 |

图只在该项写进滚动区时发一次。正在流式输出、还没形成完整块的文字不画。

宽度不超过终端列数，高度最多 20 行，保持比例。宽高从文件头读取。读不出宽高时按 40 列、12 行的框画。发给终端的是原文件字节。

Kitty 的每一行都是占位字符，Ink 按字符数行。iTerm 和 Sixel 在控制序列后面补上同样行数的空行，使滚动区高度和画面一致。

单张要画的文件超过 20 MiB 时不画。

## 失败

失败时 TUI 继续运行。收图失败写在输入框上方，灰色一行。图画不出来时，原来的路径文字还在，错误不向外抛。

| 情况 | 表现 |
| --- | --- |
| 剪贴板没有图片，或字节不是这四种图片 | `clipboard has no image` |
| Linux 上 `wl-paste` 和 `xclip` 都不存在 | `image clipboard unavailable` |
| 单张超过 20 MiB，或这条消息已有 20 张图 | 附件库现有的 `AttachmentError` 文案，这张不收 |
| 粘贴里有一条不是已存在且可读的图片 | 整段仍当文字插入 |
| 回复或工具结果的真实路径在工作区外、读失败、超过 20 MiB，或文件头不是这四种图片 | 这张不画 |
| 审批、提问或会话选择开着 | Alt+V 不读剪贴板，Backspace 不改待发送列表 |

## 测试

测试检查路径列表、协议名字、控制序列字符串和附件库。不要求 CI 的终端真的把图画出来。协议选择和剪贴板命令接收注入的环境与执行函数，不读测试机器自己的终端。

- 路径识别：Markdown 图片和工作区里的裸路径进入待画列表；网页地址、`data:`、工作区外的真实路径、同一块里的重复路径不进入；超过 20 张时只留前 20 张。
- 协议选择：上表的每一行得到对应协议，其余得到空。
- 编码：iTerm 序列带格子高度；Kitty 序列的占位字符行数与声明的行数一致；Sixel 序列非空；协议为空时结果是空字符串。
- 剪贴板：macOS、Linux、Windows 各自组装上面的命令；没有图片，或两个 Linux 命令都不在时，返回对应的那句错误。
- 粘贴：整段都是已存在的图片路径时写入附件库，输入框不留下这段字；其中一条不是图片文件时，整段仍是文字。
- 界面：带图片附件的用户消息在滚动区输出里留下所注入协议的控制序列；Alt+V 调用注入的剪贴板读取。`--plain` 的现有输出里不出现这些控制序列。
