# 设计说明：忙时排队发消息

状态：✅ 已实现（v0.37.3）

以前模型在跑时发送是禁用的，想补一句只能先停掉。本设计参照 Cursor：一轮进行中发的消息先排在输入框上方，这一轮正常结束后自动作为下一轮发出。

遵循的原则（见 [设计哲学](../guide/philosophy.md)、[`tah serve`](./serve.md)）：

- 队列属于 Application 层：放在 host（`packages/cli`），界面在 `packages/web` 和 TUI；`core` / `agent` 不改。排着的消息不插进正在跑的这一轮（Claude Code 那样要改 Agent 循环）。
    10|- 界面状态只由事件重建：队列每次变化都发完整列表，刷新页面、新开标签页都能看到。

## 规则

- **入队。** 一轮进行中调 `send`，消息（文字和附件）进队列，立即返回，不再报错。空消息、附件超限照常立即报错。
- **自动发出。** 一轮正常结束（`turn.end`，`finishReason` 不是 `max_steps`）后，取队列里第一条没暂停的消息发出，作为下一轮。`ask_user` 点 Skip 结束的那一轮也算正常结束。
- **暂停。** 一轮被停止、出错（`turn.error`）或碰到步数上限时，当时排着的消息全部标为暂停（`held`），不再自动发；之后新排进来的照常自动发。暂停的消息由用户手动发出或删除。
- **手动发出、删除。** `sendQueued(id)` 空闲时把这条移出队列并立即发出（忙时报错）；`removeQueued(id)` 删掉一条。
- **切换会话清空。** 新建、打开、fork 会话时清空队列（这些操作要求空闲，只会清掉暂停的消息）。网页换工作文件夹时换了 host，队列跟着旧 host 丢掉。
    20|
## 事件和接口

| | 内容 |
| --- | --- |
| host 事件 `queue` | `{ items: [{ id, text, attachments?, held }] }`：完整列表，界面直接替换 |
| `ChatHost.send(text, ids)` | 忙时入队 |
| `ChatHost.sendQueued(id)` / `removeQueued(id)` | 手动发出 / 删除 |
| `POST /api/send` | 忙时入队，不再返回 409 |
| `POST /api/queue` | `{ id, send: true }` 或 `{ id, remove: true }`，成功 204 |

    30|hub 记住最后一次 `queue` 事件，新标签页订阅时排在这一轮的事件后面回放。自动发出的那一轮由 host 发起，hub 从它的 `user` 事件知道又在忙了。

## 网页

- 模型在跑时输入框照常能输入、上传附件，Enter 排队；按钮仍是 Stop。
- 输入框上方列出排着的消息：每条一行，文字过长截断，有附件时显示个数，右边删除；暂停的标"paused"，多一个发送按钮（空闲时才能点）。

## 终端（`tah chat`）

- 忙时 Enter 排队。输入框上方用灰字列出排着的消息，暂停的标出来。
    40|- 输入框为空时按 ↑：最后一条排着的消息回到输入框并移出队列（同 Claude Code），改完 Enter 发出或重新排队，清空就是删掉。

## 非目标

- 插进正在跑的这一轮。
- 原地编辑、拖动排序。
- 换工作文件夹后保留队列。
